<check id="B2.CONTRACT">
Цель: проверить наличие реквизитов договора-основания (номер + дата).

Применяй сверху вниз:

Шаг 0:  Если purpose_linked_documents нет записей → FAIL, message: «Договор-основание не упомянут в назначении.». Дальнейшие шаги пропускай. Стоп.
Шаг 1:  Если в purpose_linked_documents есть запись с kind="main_contract" (или "assignment_dut") и заполнены и number, и date → PASS, message: "". Стоп.
Шаг 2:  Если ≥2 main_contract без даты, но дата у каждого следует из паттерна `<id-YY> <ДД.ММ.YY>` — считается заполненной (Шаг 0).
Шаг 3:  Если purpose_linked_documents содержит main_contract с заполненным number, но date пустая (null или "") → FAIL, message: «Дата договора не указана.»
Шаг 4:  Если main_contract есть с заполненной date, но number пустой (null или "") и в тексте нет слова «б/н» → FAIL, message: «Номер договора не указан.»
Шаг 5:  Если в payment_purpose_raw нет ни одного main_contract / assignment_dut, но при этом есть упоминание договора («ПО ДОГОВОРУ», «СОГЛАСНО ДОГОВОРУ») без номера и даты → FAIL, message: «Номер и дата договора не указаны.»
Шаг 6:  Если в payment_purpose_raw нет ни одного main_contract / assignment_dut → FAIL, message: «Договор-основание не упомянут в назначении.»
Шаг 7 (исключения — OUT_OF_SCOPE):
  • Бюджетный платёж (ГОСПОШЛИНА / КБК / ОКТМО / «ВЗЫСКАНИЕ ПО СУДУ» / «СУДЕБНЫЙ ПРИКАЗ») — реквизиты договора не нужны → OUT_OF_SCOPE, message: «Бюджетный платёж — реквизиты договора не требуются.»
  • Банковская операция («ПРОДАЖА ВАЛЮТЫ», «ПОКУПКА ВАЛЮТЫ», «КОНВЕРТАЦИЯ», «ПРОДАЖА ТОКЕНОВ», «ПЕРЕВОД СОБСТВЕННЫХ СРЕДСТВ») — основание не договор, а заявка/заявление → OUT_OF_SCOPE, message: «Банковская операция — реквизиты договора не требуются.»
  • Договор не упоминается вообще, и платёж не подходит под бюджетный/банковский → OUT_OF_SCOPE, message: «Договор-основание не упомянут в назначении.»

ЖЁСТКОЕ ПРАВИЛО (самопроверка перед выдачей ответа):
  • Если у любого main_contract поле number равно null или "" — статус B2.CONTRACT НЕ МОЖЕТ быть PASS. Только FAIL.
  • Если у любого main_contract поле date равно null или "" — статус B2.CONTRACT НЕ МОЖЕТ быть PASS. Только FAIL.
  • PASS допустим ТОЛЬКО когда есть хотя бы одна запись main_contract, у которой ОБА поля number и date — непустые строки.
</check>

<check id="B2.THIRD_PARTY">
Признаки ДУТ: «ПО ДУТ», «ДОГ. УСТ. ТРЕБ.», «ДОГОВОР УСТУПКИ ТРЕБОВАНИЙ», «УСТУПКА ТРЕБОВАНИЙ» или упоминание первоначального кредитора (в любой форме — см. ниже).

  «ПЕРВ. КРЕДИТ.», «ПЕРВ.КРЕД.», «ПЕРВОНАЧ. КРЕДИТОР», «ПЕРВОНАЧАЛЬНЫЙ КРЕДИТОР»

Цель: проверить наличие реквизитов договора-основания (номер + дата).
